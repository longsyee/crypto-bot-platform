## Known Issues from QA Reports

### Critical (Must Fix Before Production)

1. **`apps/api/src/routes/bots.ts:27`** — `zValidator` applies `BotConfigSchema` to the entire request body instead of a wrapper object `{ connectionId, name, mode, config }`. Valid requests are rejected.
2. **`apps/api/src/routes/admin.ts:82`** — `/refund` reads `amount` from raw JSON with no validation. Negative amounts decrement victim wallets (fund theft vector).
3. **`apps/wallet/src/services/hd-wallet.ts:4`** — Hardcoded fallback mnemonic (`abandon abandon ...`). If `WALLET_MNEMONIC` is unset, every wallet derives from a publicly known seed, compromising all private keys.
4. **`apps/worker/src/engine/dca-loop.ts:53-92`** — DCA `botStates` is in-memory only. On worker restart, a new base order is placed instead of restoring prior VWAP/position state, causing duplicate entries and incorrect math.
5. **`apps/worker/src/services/fee-applier.ts:18-34`** — Fee deduction is not atomic. A crash between `transaction.create` and `wallet.update` leaves a recorded fee with no balance deduction.

### High Severity

- **Frontend:** `bot-wizard.tsx` DCA breakeven math is wrong (compares to `dropPrice` instead of lowest safety-order price); wizard completes without a real API POST.
- **Backend:** `/refresh` lacks Zod validation and rate-limiting (brute-force risk).
- **Backend:** PATCH `/:id/mode` accepts arbitrary strings without enum validation.
- **Backend / Security:** `x-forwarded-for` is used without trusted-proxy validation in `rate-limit.ts`, `ip-allowlist.ts`, and `admin.ts` audit logging, allowing IP spoofing and bypass.
- **Backend:** Admin `/bots/:id/kill` does not check bot existence before update.
- **Backend:** Admin query params use naked `parseInt`, yielding `NaN` in Prisma `skip`.
- **Backend:** DCA engine references `bot.configJson` but Prisma property is `config`.

### Medium Severity

- No automatic token refresh in frontend (15-minute access tokens force frequent re-login).
- Admin `/refund` allows duplicate refunds, does not restrict transaction types, and does not reverse commission ledger entries.
- Admin audit log is created outside the refund transaction (non-atomic).
- Fee applier coerces Prisma `Decimal` to JS `number`, losing precision before multiplication.
- Encryption key length is not validated at runtime.
- `api-client.ts` has no request timeout and no CSRF protection.
- `bot-wizard.tsx` missing paper/live mode selector and DCA review step omits key fields.

### Low / Info

- `tier-card.tsx` lacks ARIA attributes on progress bars.
- `auth.ts` register endpoint returns both access and refresh tokens (acceptable for MVP, noted for v2).
- DCA live-mode key decryption is a placeholder comment only.
