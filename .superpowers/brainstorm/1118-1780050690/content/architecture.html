Communication Patterns

  • API → Worker: BullMQ queues (e.g., "bot-start", "bot-stop", "webhook-signal"). API enqueues; Worker consumes.
  • Worker → API: Redis Pub/Sub (trade events, bot status changes). API subscribes to broadcast to connected frontends via SSE or WebSockets.
  • Frontend → API: Standard HTTP REST/JSON. JWT in Authorization header.
  • TradingView / External → API: Webhook POST to `/webhooks/signal/:botId` (secured by HMAC or UUID secret).
