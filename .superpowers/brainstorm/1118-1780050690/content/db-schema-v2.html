Platform Core — Updated DB Schema (Token + Referral)

Pay-as-you-go token model + affiliate commission

Entity Relationship — Token & Referral Additions
users id (PK), email, password_hash, role (user|moderator|admin), email_verified, referral_code (unique), referred_by (FK→users, nullable), created_at, updated_at
user_balances id (PK), user_id (FK→users), token_balance DECIMAL(20,8), total_deposited, total_spent, total_earned_referral, updated_at
transactions id (PK), user_id (FK→users), type (deposit|trade_fee|referral_payout|refund), amount, currency, stripe_payment_intent_id (for deposits), metadata_json, created_at
referrals id (PK), referrer_id (FK→users), referred_user_id (FK→users, unique), commission_rate (default 10%), total_commission_earned, status, created_at
commission_ledger id (PK), referral_id (FK→referrals), trade_id (FK→bot_orders|paper_trades), source_user_id, commission_amount, status (pending|paid|reversed), created_at

Token & Fee Model Rules

  • Deposit: Users buy tokens via Stripe (one-time payment). 1 token = $1 USD for simplicity.
  • Fee trigger: 20% fee charged only on winning trades. Losing trades = $0 fee.
  • Fee calculation: Fee = realized_pnl × 0.20. Deducted from user_balances.token_balance immediately on fill.
  • Insufficient balance: If token balance < fee, bot auto-pauses and sends alert. User must top up.
  • Paper mode: No fees deducted, but simulated fees are tracked in paper_trades.simulated_fee for transparency.

Referral Program Rules

  • Referral code: Every user gets a unique code (e.g., REF-ABC123) on signup.
  • Commission: Referrer earns % of trading fees paid by their referred user. Default 10% of the 20% fee (i.e., referrer gets 2% of winning PnL, platform keeps 18%).
  • Payout: Commission credited to referrer's user_balances.token_balance as type='referral_payout'.
  • Tracking: commission_ledger links each payout to a specific trade for audit.
