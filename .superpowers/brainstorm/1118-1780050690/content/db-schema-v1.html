Platform Core — Database Schema

Key tables and relationships (PostgreSQL)

Entity Relationship Overview
users id (PK), email, password_hash, role (free_user|premium_user|moderator|admin), email_verified, created_at, updated_at
subscriptions id (PK), user_id (FK→users), stripe_customer_id, stripe_subscription_id, tier, status, current_period_end, cancel_at_period_end
exchange_connections id (PK), user_id (FK→users), exchange_id, name, api_key_encrypted, api_secret_encrypted, passphrase_encrypted, is_testnet, is_active, created_at
bots id (PK), user_id (FK→users), connection_id (FK→exchange_connections), name, type (signal|dca), status (stopped|running|paused|error), mode (paper|live), config_json, created_at, updated_at
bot_orders id (PK), bot_id (FK→bots), exchange_order_id, symbol, side, type, amount, price, status, filled, remaining, cost, fee, fee_currency, raw_ccxt_response_json, created_at, updated_at
bot_logs id (PK), bot_id (FK→bots), level (info|warn|error), message, metadata_json, created_at
paper_trades id (PK), bot_id (FK→bots), symbol, side, amount, price, simulated_fee, total_cost, pnl, created_at
bot_comments id (PK), bot_id (FK→bots), user_id (FK→users), content, is_public, rating, parent_id (self-FK for threads), created_at, updated_at

Design Notes

  • Encrypted at rest: api_key_encrypted, api_secret_encrypted, passphrase_encrypted use AES-256-GCM with an app-level master key. Master key stored in env, never in DB.
  • Bot polymorphism: bots.config_json stores type-specific settings (signal webhook secret, DCA levels, martingale ratios). Validated by Z schemas per type.
  • Indexing strategy: bots(user_id, status) for dashboard listings. bot_orders(bot_id, created_at DESC) for trade history. bot_logs(bot_id, created_at DESC) for log viewer.
  • Tier enforcement: A middleware checks subscriptions.tier and status='active' before allowing bot creation / activation. Free tier = max 2 bots, 1 connection.
