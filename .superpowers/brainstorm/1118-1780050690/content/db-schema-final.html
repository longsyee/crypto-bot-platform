Platform Core — Final Database Schema (with Wallet Service)

All tables: users, wallet, bots, orders, logs, referrals, admin

Users & Wallet
users id (PK), email, password_hash, role (user|moderator|admin), email_verified, referral_code (unique), referred_by (FK→users), created_at, updated_at
wallets id (PK), user_id (FK→users), bsc_address_index (int), bsc_address (varchar), usdt_balance DECIMAL(20,8), token_balance DECIMAL(20,8), total_deposited, total_withdrawn, total_fees_paid, total_earned_referral, updated_at
transactions id (PK), wallet_id (FK→wallets), type (deposit|withdraw|convert_in|convert_out|trade_fee|referral_payout|refund|admin_adjust), amount, currency (USDT|TOKEN), status (pending|confirmed|failed|reversed), tx_hash (for on-chain), metadata_json, created_at
Exchange & Bots
exchange_connections id (PK), user_id (FK→users), exchange_id, name, api_key_encrypted, api_secret_encrypted, passphrase_encrypted, is_testnet, is_active, created_at
bots id (PK), user_id (FK→users), connection_id (FK→exchange_connections), name, type (signal|dca), status (stopped|running|paused|error), mode (paper|live), config_json, created_at, updated_at
bot_orders id (PK), bot_id (FK→bots), exchange_order_id, symbol, side, type, amount, price, status, filled, remaining, cost, fee, fee_currency, fee_rate_at_entry, raw_ccxt_response_json, created_at, updated_at
bot_logs id (PK), bot_id (FK→bots), level (info|warn|error), message, metadata_json, created_at
paper_trades id (PK), bot_id (FK→bots), symbol, side, amount, price, simulated_fee, total_cost, pnl, created_at
Referral & Admin
referrals id (PK), referrer_id (FK→users), referred_user_id (FK→users, unique), tier (bronze|silver|gold|platinum|pending_kol|kol), commission_rate, total_commission_earned, status, created_at
commission_ledger id (PK), referral_id (FK→referrals), transaction_id (FK→transactions), source_user_id, commission_amount, status (pending|paid|reversed), created_at
bot_comments id (PK), bot_id (FK→bots), user_id (FK→users), content, is_public, rating, parent_id (self-FK), created_at, updated_at
admin_audit_log id (PK), admin_user_id (FK→users), action (kill_bot|refund|approve_kol|change_fee|edit_config|suspend_user), target_type, target_id, old_value_json, new_value_json, ip_address, created_at
security_events id (PK), user_id (nullable), event_type (failed_webhook|invalid_login|suspicious_referral|rate_limit_exceeded), ip_address, details_json, created_at

Wallet Service Tables (in Wallet Service DB, or shared schema)

  • deposit_addresses id, user_id, address_index, bsc_address, status (active|archived), created_at
  • blockchain_events id, tx_hash, from_address, to_address, amount, token_contract, block_number, confirmations, status (pending|confirmed|invalid), matched_user_id, created_at
  • withdrawal_requests id, user_id, amount, to_address, tx_hash, status (pending|processing|completed|failed), fee_estimate, processed_at, created_at

These can live in a separate Wallet Service DB (SQLite or Postgres) or shared Postgres with separate schemas. Recommendation: separate lightweight SQLite for Wallet Service to keep it self-contained, with HTTP callbacks to Main API.
